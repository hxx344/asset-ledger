# CI 运行包部署

原有一键安装命令保持不变，默认下载已经通过 CI 并明确发布的正式运行包。`PROJECT_DEPLOY_MODE=source` 或 `--rebuild` 使用源码构建。选择源码模式时，将原命令中的 `sudo bash` 改为 `sudo env PROJECT_DEPLOY_MODE=source bash`。

CI 在 Ubuntu 22.04 x64、ARM64 原生构建 Next standalone 服务，将 static、public、数据库迁移和配置备份脚本一起打包。每个架构都启动解包后的服务验证功能。服务器根据架构选择制品，校验 SHA-256 和提交身份，在独立版本目录中准备更新。升级保留密码、加密密钥、资产及历史；启动失败时恢复原版本、部署配置和数据库备份。

`main` 的全部必要检查通过、两个架构均可用后，仅发布固定 `deploy-<完整提交号>` 候选标签和清单（`prerelease`）。发布者在 **Publish stable release** 工作流选择 `main`，输入已通过本仓库 CI 的完整 40 位提交 SHA，核验后晋级为最新正式版；默认安装及工作台前端更新只使用正式版。失败构建和未晋级候选不改变现有正式版，晋级流程拒绝回退到旧提交或不同历史。无可用正式制品或校验失败会停止更新并保留现有服务，可明确选择源码模式处理。

运行内容未变时，只核对清单和服务健康，不重复下载包、安装项目依赖、构建、备份或重启。文档、测试和 CI 工作流变更不会单独导致服务重启。安装日志分别列出已检查提交和实际运行产物提交。总部署预检过的清单直接传入安装器，避免更新途中换成另一份清单。
