# CI 运行包部署

原有一键安装命令保持不变。目前默认仍为源码构建；为首次制品发布保留兼容窗口。使用 `PROJECT_DEPLOY_MODE=ci` 运行安装器可下载已经通过 CI 的运行包，例如将原命令中的 `sudo bash` 改为 `sudo env PROJECT_DEPLOY_MODE=ci bash`。`PROJECT_DEPLOY_MODE=source` 或 `--rebuild` 使用源码构建。

CI 在 Ubuntu 22.04 x64、ARM64 原生构建 Next standalone 服务，将 static、public、数据库迁移和配置备份脚本一起打包。每个架构都启动解包后的服务验证功能。服务器根据架构选择制品，校验 SHA-256 和提交身份，在独立版本目录中准备更新。升级保留密码、加密密钥、资产及历史；启动失败时恢复原版本、部署配置和数据库备份。

部署清单只有在全部必要检查通过、两个架构均可用且仍是 main 最新提交时才发布。清单引用固定 `deploy-<完整提交号>` 标签下的包。无可用制品或校验失败会停止更新并保留现有服务，可明确选择源码模式处理。

运行内容未变时，只核对清单和服务健康，不重复下载包、安装项目依赖、构建、备份或重启。文档、测试和 CI 工作流变更不会单独导致服务重启。安装日志分别列出已检查提交和实际运行产物提交。
